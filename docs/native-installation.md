# Native candidate installation — 0.2.0-rc.2

This is a prerelease candidate for Windows x64 and experimental Mac Intel/Apple Silicon, not a stable compatibility promise. Mac archives are **UNSIGNED and NOT NOTARIZED**: ordinary assisted auto-install must stop and explain the explicit developer/experimental route. If macOS blocks opening the executable, stop; do not remove quarantine, bypass Gatekeeper, disable protection or request administrator access. A successful build or CI run is not evidence of first-use desktop authorization, real Agent loading or phone delivery. The packaged Skill can guide local setup; reading the repository or importing the Skill does not install software, enable a daemon, or send notifications. Publication requires exact-tag native/legacy/package gates; see the version-scoped online [validation record](https://github.com/kj858bp8g2-ship-it/agent-task-notify/blob/v0.2.0-rc.2/docs/native-validation.md).

## Obtain and check the package

Use only `kj858bp8g2-ship-it/agent-task-notify`, its reviewed exact `v0.2.0-rc.2` prerelease (when published), or its exact candidate workflow run and source commit. Release assets are the three Agent Task Notify (ATN) archives and combined `SHA256SUMS`: `atn-native-0.2.0-rc.2-windows-amd64.zip`, `atn-native-0.2.0-rc.2-darwin-amd64.tar.gz`, `atn-native-0.2.0-rc.2-darwin-arm64.tar.gz`. Before publication, matching `native-candidate-windows-amd64`, `native-candidate-darwin-amd64` or `native-candidate-darwin-arm64` artifacts each hold one archive and its checksum file. Confirm repository, tag/run, source commit and artifact provenance before trusting its checksum. SHA256SUMS detects corruption; an attacker can replace both archive and checksum, so hashes alone are not publisher authentication. Do not use curl-to-shell installers.

Compare the archive's SHA-256 with its one matching basename in SHA256SUMS before extracting. Windows has `certutil -hashfile ARCHIVE SHA256`; macOS has `shasum -a 256 ARCHIVE`. Inspect the archive list first: it must match `manifest.json`'s fixed list and contain no absolute paths, `..`, duplicates or links. Extract into a new user-owned folder, never over an old install. Mac must use the tar.gz, preserving executable permissions (do not transfer the bare binary through ZIP). Keep both INSTALL files, manifest, notices, Skill and integrations with the executable. Defaults and eight Agent icons are embedded; there is no mutable config or icon copy to install.

For developer-level strict verification from the reviewed source checkout, with Go already installed, use:

```text
go run ./cmd/package-native verify --archive ABS_ARCHIVE --checksums ABS_SHA256SUMS --platform PLATFORM --version 0.2.0-rc.2 --extract-to ABS_NEW_FOLDER
```

Replace path placeholders with **clean canonical OS-native absolute paths**, not merely strings your shell accepts as absolute. The developer verifier requires `filepath.Clean(path) == path`: avoid `.`/`..`, redundant separators and trailing separators on non-root paths; on Windows use native backslashes, not forward/mixed separators. In Windows PowerShell, obtain existing archive/checksum paths from `(Get-Item -LiteralPath 'ABS_ARCHIVE').FullName` (likewise for the checksum file); normalize the chosen new, still-absent target with `[IO.Path]::GetFullPath('ABS_NEW_FOLDER')`. Replace those placeholders with your selected absolute locations and pass the resulting values quoted, especially spaces (for example `--archive "$archive" --checksums "$checksums" --extract-to "$extract"`). This is caller path formatting, not permission repair or a bypass of the remaining checks.

Verification checks the hash, exact archive name/list, sizes, modes, platform, architecture, all four identical binary copies and manifest before running the extracted program. It accepts only the current OS/architecture. **The caller must choose an existing owned parent outside the source checkout** for the new extract-to leaf: verifier isolation is a sibling of that leaf, not an automatic source-outside guarantee. It creates a new explicitly owned folder and isolated temporary user/data/CWD paths, runs version, doctor and eight previews with empty PATH, and never sends or opens Keychain. The developer verifier expects the matching artifact's single-entry checksum file; for the release's combined SHA256SUMS, first select its one exact basename entry into a separate local file without changing the hash. It is a developer tool, not an end-user runtime requirement. The program itself needs no separately installed PowerShell, Node, Python or Go; the Agent's own runtime and selected host command shell remain the Agent's prerequisites.

## Inspect, configure, then install explicitly

Use the absolute path to the extracted executable (`agent-task-notify.exe` on Windows, `agent-task-notify` on Mac). All commands below start with that path. In a shell that requires it, quote it or use the shell's invocation operator. Choose an independent user-owned data directory outside the package, source checkout and legacy data. New defaults are `%LOCALAPPDATA%\AgentTaskNotifyNative` (Windows) and `$HOME/Library/Application Support/AgentTaskNotifyNative` (Mac); the default's parent must exist. Explicit `--data-directory ABS_DATA` overrides `ATN_DATA_DIRECTORY`, which overrides these defaults. Keep the same data path for every step and future hook.

```text
agent-task-notify version
agent-task-notify doctor --data-directory ABS_DATA
agent-task-notify preview --agent codex --data-directory ABS_DATA
agent-task-notify configure --provider bark --data-directory ABS_DATA
```

Use `bark` for iOS or experimental `ntfy` for Android. Configuration asks for credentials in a local hidden terminal prompt; never paste a token, device key, complete private URL or config file into Agent chat or command arguments. Nonterminal input requires explicit `--credential-stdin` from an authorized local source. Optional `--settings-file ABS_JSON` is a local nonsecret settings patch. Credentials and exact host backups use Windows CurrentUser DPAPI / Mac Keychain-backed encryption; no plaintext or CLI security fallback. Only explicit configuration or foreground Vault operations during authorized applied installation/removal may create/authorize Mac Keychain keys. Doctor and dry preview read syntactic settings/envelope presence without decryption or Keychain: configured does not prove valid credentials, unlocked keys or service acceptance. Plain preview sends nothing; only explicit `preview --agent ID --send` authorizes an optional audible test. Queued/sender-accepted does not prove phone arrival. Do not use `--send` in package checks. ntfy topics need verified server ACLs; a random name or bearer token alone does not prove privacy, and unauthenticated opt-in accepts exposure.

Agent IDs are `codex`, `claude-code`, `cursor`, `gemini-cli`, `opencode`, `workbuddy`, `openclaw`, `hermes`. The first five have receipt-owned automatic registration; preview before applying:

```text
agent-task-notify install --agent codex --command-shell cmd --data-directory ABS_DATA
agent-task-notify install --agent codex --command-shell cmd --data-directory ABS_DATA --apply
```

The Windows example assumes the host actually uses cmd; select `powershell` or `posix` only for a verified corresponding host shell. Mac hosts use explicit `--command-shell posix`. Do not infer the host shell from your interactive terminal. `--config-path ABS_FILE` selects an explicitly verified host config: default targets are `.codex/hooks.json`, `.claude/settings.json`, `.cursor/hooks.json`, `.gemini/settings.json` under the user's home; OpenCode uses `$XDG_CONFIG_HOME/opencode/opencode.json` or `$HOME/.config/opencode/opencode.json` as a locator and writes only its sibling `plugins/agent-task-notify.js`. The host target parent (including OpenCode's plugins directory) must already exist and be user-owned: the installer never creates/repairs host directories. For a missing parent, stop, verify the host's intended location and have it created/verified locally before retrying; do not repair permissions or elevate. Existing empty/whitespace/malformed JSON stays untouched and needs explicit handling. Review the printed target/plan, then use `--apply` only with authorization. Unknown fields/hooks and JSON number lexemes are preserved; a protected backup and receipt are required (host file limit 4 MiB, encrypted envelope 6 MiB). Conflicts stop rather than overwriting. The two-second installer lock is an acquisition wait, not a hard limit on OS calls or installation; foreground Vault authorization occurs before locking. Codex's existing `notify` configuration is not replaced; finish any host trust/approval step yourself. Importing the Skill does **not** activate background hooks. A receipt cannot detect every alternate plugin route or prove host loading.

OpenCode loads the packaged JS bridge in its own runtime, then spawns the native executable directly. Keep the `integrations/opencode` folder beside the root binary; the native installer creates a shim with the explicit executable/data path. Do not import the legacy default wrapper as a substitute for that native installation. Never double-register the legacy PowerShell/plugin route with the native route. This candidate leaves your current installation unchanged: it does not upgrade it or read old device keys. The separate legacy source route includes a narrowly verified worker startup-lock correction; this does not establish a cause for every historical timing failure.

## WorkBuddy manual experimental package

Manually import the complete `workbuddy` subfolder using an explicitly verified host plugin workflow; no desktop settings file is guessed or written automatically. It includes `.workbuddy-plugin/plugin.json`, `hooks/hooks.json`, `hooks/launch.sh` and the matching `runtime` binary. The host's Bash uses `CODEBUDDY_PLUGIN_ROOT`, falling back to `CLAUDE_PLUGIN_ROOT`; no separately installed notification runtime is needed. Configure the **WorkBuddy copy** of the binary with the same chosen data directory, and supply `ATN_DATA_DIRECTORY` to the host if using a nondefault path. Wrong OS, missing binary or execution failure produces a neutral response. Desktop loading, cancellation and actual delivery remain unverified; do not install legacy and native WorkBuddy packages together.

## OpenClaw and Hermes manual experimental packages

OpenClaw uses the complete `openclaw` subfolder and its official typed `before_agent_run`/`agent_end` plugin hooks. Review `openclaw/README.md`, install/link and enable it through the OpenClaw CLI, explicitly grant `hooks.allowConversationAccess`, then restart and inspect the Gateway. The bridge discards prompts/messages and forwards only lifecycle/session/run fields; observed subagent sessions are ignored. A Gateway restart during a run loses in-memory correlation. Real OpenClaw host loading remains untested.

Hermes uses the complete `hermes` subfolder and official Shell Hooks. Merge the two reviewed commands in `hermes/config.example.yaml` into the existing `~/.hermes/config.yaml`; do not overwrite other hooks or enable global auto-accept. `pre_llm_call` starts a turn and `on_session_end` closes success/failure/interruption. Follow `hermes/README.md`, use absolute paths (forward slashes on native Windows), run `hermes hooks doctor`, and approve each exact `(event, command)` pair on first use. Real Hermes host loading remains untested.

## Defaults and removal

The timer starts with a supported task start; repeats do not reset it and repeated end events do not create a second main job. Tunable defaults: `minSeconds: 1800`, `longTaskSeconds: 3600`, `mediumRingSeconds: 45`, `longRingSeconds: 60`, `continuous: true`, `level: critical`, `volume: 7`, `sound: alarm`, `ntfyPriority: 4`, `enableAttention: false`, `icons: {}`. Thresholds must be positive/ordered; ring targets 30–60 seconds, volume 0–10, priority 1–5. Use a local JSON patch, e.g. `{"minSeconds":300,"longTaskSeconds":1200,"sound":"alarm"}`, with configure's `--settings-file`; credentials are still entered locally. Do not edit embedded defaults. Continuous Bark uses two notifications (main plus one extension), so duplicates in phone history are expected; 45/60 are approximate targets, not guaranteed audible duration. Single mode follows the sound's own duration. ntfy sound is controlled by the phone; it sends no Call/X-Call or Bark-only sound fields. Neither provider makes a real telephone call.

Each Agent has its own remote icon metadata: Codex/ChatGPT, Claude Code/Claude, Cursor, Gemini CLI/Gemini, OpenCode, WorkBuddy, OpenClaw, and Hermes Agent. These decorate notifications, not application/system small icons. Remote URLs can change and imply no brand license; an `icons` override maps one of the eight known IDs to HTTPS artwork, with empty/invalid artwork omitted. The `sound` value and each individual icon override are limited to 4096 UTF-8 bytes. Settings/icons freeze when a job is created. There is no extra telemetry; the selected service necessarily receives its credential and generic content, not task text, paths or native IDs. Local encryption is not end-to-end push encryption.

No adapter guarantees all `needs_attention` moments. Sources without native run IDs can ambiguously correlate delayed Stop events. Main retry is bounded at five attempts with waits 5/15/30/60 seconds for explicitly retryable errors; extension is attempted once. There is no offline queue guarantee, service/restart/reboot recovery, or exactly-once/phone-arrival promise. Crash gaps exist between state → job → spawn; uncertain sends are not replayed. A final check can race a later event. The worker's 240 seconds is a cooperative context budget, not a hard OS process-kill/containment guarantee.

Preview `uninstall --agent ID --data-directory ABS_DATA`, then repeat with `--apply` only after review. It removes only receipt-confirmed native entries; it does not restore an entire config or delete user/data folders. Keep the original package until uninstall completes: filesystem identity checks may safely refuse after it is deleted. Edited-owned-entry conflicts require local review, not blind restoration. WorkBuddy, OpenClaw, and Hermes removal is manual through each verified host workflow; the CLI intentionally refuses automatic uninstall for them. For legacy rollback, disable/remove native registration first, retain protected backups/data, then explicitly re-enable one reviewed legacy route with its original separate data. Never read/migrate old keys or overwrite live hooks automatically. Do not recursively erase directories or delete Keychain items as an automated cleanup step.

Read-only or unsupported filesystems, nonprivate roots, links/reparse points, unknown ownership/security metadata and some OS-valid names are safely refused without repair. Source isolation checks only exact ancestor `.git` or this project's `go.mod` plus `config/native-source-files.json` markers; it cannot universally identify unmarked source trees and is not a universal leak guarantee. Trusted OS-owned ancestors do not make shared service-owned paths acceptable or relax current-user-only private roots. See online [compatibility limits](https://github.com/kj858bp8g2-ship-it/agent-task-notify/blob/v0.2.0-rc.2/docs/native-compatibility.md) for OS metadata boundaries and [legacy guidance](https://github.com/kj858bp8g2-ship-it/agent-task-notify/blob/v0.2.0-rc.2/README.md#legacy-windows-route) for the separate Windows script option.
